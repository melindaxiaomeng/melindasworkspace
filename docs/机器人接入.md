# 机器人接入：飞书 / 企微 群消息 → 自动落库看板

> 目标：群里的客户需求 / Bug 吐槽，机器人静默抓取 → 后端 AI 结构化提取 → 自动生成「需求卡片」落入看板「收件箱」。
> 已实现：后端 `server.js` 的 `POST /api/ingest`（通用）、`/api/ingest/feishu`、`/api/ingest/wecom`，以及 `POST /api/ai/extract`（仅提取不落库）。

---

## 0. 安全前提（必读）

- 看板本身已有 `API_TOKEN` 网关（`Authorization: Bearer <API_TOKEN>`）。部署后所有 `/api/` 都需要它。
- 机器人接口额外用 **`INGEST_SECRET`** 做二次鉴权：服务端配置该环境变量后，调用 `/api/ingest*` 必须带请求头 `X-Ingest-Secret: <INGEST_SECRET>`，否则返回 `401`。
- 强烈建议 `INGEST_SECRET` 与 `API_TOKEN` 设为**不同**的值。

部署时在 `deploy/aliyun/.env` 增加一行：

```bash
INGEST_SECRET=一串你自己定的随机串（如 openssl rand -hex 16）
```

---

## 1. 通用接口（最简，推荐先用这个验证）

无论飞书还是企微，都可以在你自己的转发脚本里把消息整理成统一格式，POST 到：

```
POST /api/ingest
Headers:
  Authorization: Bearer <API_TOKEN>
  X-Ingest-Secret: <INGEST_SECRET>
  Content-Type: application/json
Body:
{
  "text": "原始聊天内容",
  "sender": "发送人名称",
  "group": "群名称",
  "source": "微信客户群-A"   // 可选，覆盖默认来源
}
```

返回：
- `201` 已落库（返回新建的卡片对象）
- `200 { "status": "filtered_out" }`：AI 判定为非需求闲聊，已静默丢弃（不入库）
- `401` 密钥错误；`400` 文本为空或 AI 未配置

**curl 自测示例**（本地 Mock 模式）：

```bash
curl -X POST http://localhost:3000/api/ingest \
  -H "X-Ingest-Secret: sec123" \
  -H "Content-Type: application/json" \
  -d '{"text":"支付结算页报错500","sender":"客户乙","group":"VIP群"}'
```

仅想看 AI 提取结果、不落库：

```bash
curl -X POST http://localhost:3000/api/ai/extract \
  -H "Content-Type: application/json" \
  -d '{"text":"DMP能支持实时送点击吗","sender":"客户甲","group":"客户群A"}'
```

## 2. 飞书接入

### 2.1 在飞书开放平台
1. 创建**企业自建应用**，拿到 `App ID` / `App Secret`。
2. 申请权限：`im:message`（读取消息）、`im:message:receive_as_bot`（接收消息）。
3. 在「事件订阅」中：
   - 请求地址（回调 URL）= `https://workspace.teensing.com/api/ingest/feishu`
   - 事件：勾选「接收消息 v2.0 / 消息事件（receive message）」
4. 保存时飞书会发 `url_verification` 挑战，需要回 `challenge` 值。**这一步建议放在下面的转发脚本里做**（见 2.3），不要直接把裸地址给飞书，否则 `challenge` 校验会失败。

### 2.2 把机器人拉进目标群
在飞书客户端把该应用机器人拉入需要监听的客户/内部群。

### 2.3 建议的转发脚本（做签名校验 + challenge 应答 + 转统一格式）
飞书回调带 `timestamp` + `sign` 签名，裸接不安全。在你服务器上放一个轻量 Node/Python 转发服务，它：
1. 校验飞书签名（用 `App Secret` 与 `timestamp`）；
2. 处理 `url_verification` 回 `challenge`；
3. 仅把 `message` 事件里的 `content.text` 取出来，带 `API_TOKEN` + `INGEST_SECRET` POST 给 `/api/ingest/feishu`。

> 后端 `normalizeFeishu()` 已能从飞书事件的 `event.message.content` 里提取 `text`、从 `sender_id.open_id` 提取发送人、从 `chat_id` 提取群。转发脚本只要把原始事件原样转发即可（注意带好两个鉴权头）。

## 3. 企微接入

### 3.1 在企业微信管理后台
1. 创建**自建应用**，拿到 `CorpID` / `AgentId` / `Secret`。
2. 在「接收消息」中配置：
   - 回调 URL = `https://workspace.teensing.com/api/ingest/wecom`
   - Token / EncodingAESKey（用于消息解密）
3. 同样有 `GET` 校验（`echostr`），建议在转发脚本里处理。

### 3.2 进群监听
用配置了「客户联系」/「群机器人」的企微账号加入客户群；群内新消息会经企微后台推到回调。

### 3.3 解密与转发
企微消息是 AES 加密的 XML/JSON，后端 `normalizeWecom()` 直接处理的是**已解密的明文 JSON**（字段 `Content`/`FromUserName`/`ChatId`）。因此同样建议用一个转发脚本先解密，再把明文 POST 给 `/api/ingest/wecom`（带两个鉴权头）。

## 4. 字段对照（落库后卡片长这样）

| 看板字段 | 来源 |
|---|---|
| 内容概述 summary | AI 提炼的 title（15 字内） |
| 分类 category | AI 判别：功能Bug / 新需求 / 接口与数据异常 / 操作咨询 |
| 影响模块 module | AI 判别：DMP / SAAS系统 / 数据报表 / 网盟Mapping / 支付结算 / 其他 |
| 优先级 priority | AI 判别：高 / 中 / 低（默认中） |
| 提报人 reporter | 消息发送人 |
| 来源 source | 群名称 / 你传的 source |
| 原始消息 rawMessage | 原始聊天文本（留档） |
| AI 分析 aiAnalysis | AI 给出的核心问题分析与建议 |
| 状态 status | 固定 `inbox`（收件箱），待人工派单 |

卡片进「收件箱」后，由产品经理在「团队总池」视图审核、指派责任人、拖入「本周待做」，自动同步到对方的「我的看板」。

## 5. 排查
- 飞书/企微回调 5xx → 先确认转发脚本能正常转发，再看看板容器日志 `docker logs kanban-pool`。
- `/api/ingest` 返回 401 → `INGEST_SECRET` 不一致；若你没设 `INGEST_SECRET` 环境变量，则不需要 `X-Ingest-Secret` 头。
- 返回 `{ "status": "filtered_out" }` 属正常：AI 把这条当成闲聊丢掉了。
- 真实 AI 提取需要 `AI_API_KEY`（或 `AI_MOCK=1` 走 Mock）。本地自测建议先用 `AI_MOCK=1`。
